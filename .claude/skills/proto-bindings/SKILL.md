# Proto schemas and bindings

schema/ holds every proto. strims-proto compiles it at build time with
protox (crates/strims-proto/build/main.rs), so its Rust types are never
committed. The UI's `src/apis` (TS) and infra's `pkg/apis` (Go) are
committed and are regenerated by `hack/protogen.sh` in the same commit as
any change under schema/ (crates/CONVENTIONS.md, "Formats").

## Regenerating

The bindings reproduce only with the generators they were made with:
protoc 3.21.12, protoc-gen-go v1.28.1 (go.mod's google.golang.org/protobuf),
and MemeLabs/protobuf's ts, tsrpc and gorpc plugins (protoc-gen-ts,
protoc-gen-tsrpc, protoc-gen-gorpc) built at their pinned versions. The
dev machine's private notes hold how to build them. Check
`protoc --version`, then put the plugins first on PATH:

    PATH=<plugin dir>:$PATH bash hack/protogen.sh

- TS reproduces exactly: only the messages you changed differ in
  `src/apis`.
- Each Go file's header names the protoc version that made it, so every
  file in `pkg/apis` made by an older protoc gets a one-line header diff.
  Restore those files, and keep the ones the schema change touched. This
  is safe in a worktree, but never in a checkout with other sessions'
  changes:

      git diff --numstat -- pkg/apis > target/protogen-numstat.txt
      awk '$1 == 1 && $2 == 1 {print $3}' target/protogen-numstat.txt > target/protogen-header-only.txt
      git checkout --pathspec-from-file=target/protogen-header-only.txt

  First check that the listed files' diffs are only the `// protoc` line.
  Afterwards, `git diff --stat -- pkg/apis` should list only the files of
  the changed protos.
- In a worktree-isolated session the guard rejects `$(...)`, pipes into
  git and git inside scripts. Run each git step above as its own command.
- Then build what reads the bindings: `pnpm run typecheck`,
  `go build ./...` (infra imports `pkg/apis`), and the Rust crates that
  use the changed messages.

## Evolving a message

- **Between peers: add-only.** New fields, oneof members and enum values
  go under new tags. A removed field's tag and name become `reserved`,
  and no tag is reused (CONVENTIONS "Formats").
- **Same-version: renumber freely.** CONVENTIONS makes stored records
  (strims-dao) and the UI's frontend API same-version: the UI is built
  with its node, and no old reader exists. Drop a field from such a
  message without `reserved`, and renumber its fields from 1. First check
  that neither peers nor infra's Go code read the message. A change to a
  stored record's encoding or meaning bumps `STORE_VERSION`
  (crates/strims-dao/src/store.rs).
- Golden vectors (a crate's `golden/`) pin the wire and store formats. A
  deliberate change rewrites them in the same commit:
  `STRIMS_GOLDEN=update cargo test -p <crate> --test <test>`.

## RPC error codes

An RPC error carries a code from its owner's `ErrorCode` enum, declared
in a `<package>.errors` package. crates/strims-proto/build/errors.rs
gives each package a range, and the build fails on a value outside its
range, an `ErrorCode` enum in an unlisted package, an enum nested in a
message, or overlapping ranges. `0` is `UNDEFINED`, meaning no code.
Callers branch on codes, never on messages: a code is immutable, and a
message's wording isn't.

To add codes:

- Add values to the owner's existing enum, inside its range.
- A new owner adds `schema/<path>/errors/errors.proto` (package
  `<package>.errors`) with its `ErrorCode` enum, and gives it a range in
  `RANGES` that doesn't overlap.
- Register its TS enum in `src/lib/rpcError.ts` (`errorCodeEnums`), which
  `errorCodeName` and `formatError` read. src/lib/rpcError.test.ts fails
  when a generated error enum is missing there.
